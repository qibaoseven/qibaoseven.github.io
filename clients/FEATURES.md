# 功能对齐清单（网页端 → 各原生端）

网页端（`js/pages/`）目前有 17 个功能页。这份清单把每一页对应到原生端的落地情况与接口，
作为后续逐轮补齐的依据。**别按"有没有写"理解，按"验证状态"理解**：只有 CLI / Qt 两端是真编译过的。

## 为什么刷录/串口只留在网页端

| 端 | 能否读 Web Serial / 原生串口 | 结论 |
|---|---|---|
| 桌面 Chrome / Edge | ✅ Web Serial + WebUSB | 网页端用 **esp-web-tools**（Espressif 官方）一键刷；已接 Release 里的 `hw-latest` 资产 |
| Linux CLI / Qt 桌面 | ✅ 有 `/dev/ttyUSB*`，能直接调 `esptool.py` | 未接 UI，但命令行天然可用 |
| Android | ❌ Chrome for Android 没有 Web Serial；原生要自研 USB-Serial + esptool 协议 | 端上提示"无法刷录"，给 Termux 脚本兜底（`clients/android/tools/flash-termux.sh`） |
| iOS / iPadOS | ❌ 系统不开放 USB 串口 | 明确写"无法使用" |
| 鸿蒙 / tvOS / watchOS / visionOS | ❌ 无串口栈 | 明确写"无法使用" |

## 后续补齐顺序（建议）

- **P0**（一次做完）：Android / 鸿蒙 / Swift 四端补 初始化向导、作业种类、学生历程 —— 这三块和"交作业"强相关，老师日常就要用
- **P1**：分数 / 金币 / 抽奖 / 排名 —— 都是「读班级数据 + 改一个数值」，结构简单，可复制同一套页面骨架
- **P2**：日志 / 备份 / 职位 / 考试 / 每日汇报 / 自动事件 —— 低频甚至管理员专用，放最后；部分（备份、自动事件）建议仍只在网页端做

每加一页都要同步：
1. 该端 `Api` 层加对应方法（四套后端的路径一致）
2. 权限：网页版每个页面有 `permission` 字段（如"分数管理"），客户端要把当前用户角色一起拉下来再决定显不显示
3. 写操作一律二次确认（现有 UI 都遵循这个习惯）
